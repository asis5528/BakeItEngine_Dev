# BakeIT Engine — Migration Plan

**Status:** Step 4. Executes the structure in `BAKEIT_ARCHITECTURE_TARGET.md`.
**Golden rule:** the engine builds and runs after **every phase**. Build is Visual Studio only (no CLI build), so each phase ends with: *user builds Debug|x64 in VS, runs, sculpts with the brush, resizes the viewport, drops a model.* That 2-minute smoke test is the gate to the next phase.

**Mechanics that apply to every file move:**
- Update `VulkanEngine.vcxproj` (`<ClCompile>/<ClInclude>/<None>` paths) **and** `VulkanEngine.vcxproj.filters`.
- Update every `#include "..."` that referenced the old path.
- Shader moves additionally update: both `compile.bat` files (until Phase 2 collapses them), the C++ `.spv` load paths, and the `.spv` output location.
- One commit per numbered item below (small, revertable).

## Risk notes

- **Phase 3 include churn** is the big one; do it in one sitting with VS open, not piecemeal.
- **The `.vcxproj.filters` file** must mirror every move or VS shows ghost entries; harmless but confusing.
- **`.spv` outputs** sit next to sources; moving a shader folder moves where compile.bat writes and where C++ reads — all three must change together.
- **`main()` runs `system("compile.bat")` from repo root** — the root script is canonical; whatever Phase 2 produces, the root copy is the one that matters at runtime.
- **Pottery is the crown jewel.** Phases that touch it (4.2, 5.1, 6.4) are move-only or state-relocation-only; behavior changes to the edit pipeline are out of scope for this entire migration.
